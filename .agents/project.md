# Project profile

## About

- What this repository is: `deadline-budget`, a Python library for request deadline budget tracking in distributed orchestrations, published on PyPI.
- Who uses it: services that pass a request's deadline across calls and processes.
- Language, version and main frameworks: Python 3.10 and newer, no runtime dependencies; optional extras `settings` (Pydantic) and `dishka` (Dishka integration), in `deadline_budget/contrib/`.
- Where the documentation lives: https://bedrock-python.github.io/deadline-budget/, built with Zensical from `docs/` (`zensical.toml`). `docs/agents.md` is the one-page reference for coding assistants.

## Commands

| Task | Command |
|---|---|
| Install dependencies | `uv sync --group dev --all-extras` (`make install`). Without `--all-extras`, `tests/unit/contrib/` fails at collection. |
| Format | `make fmt`: `uv run ruff format .`, then `uv run ruff check --fix .` |
| Lint and type-check | `make check`: `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy deadline_budget` |
| Test | `make test-unit` (`uv run pytest -m unit`). CI runs `uv run pytest -m unit --cov=deadline_budget --cov-fail-under=90` on every Python version of its matrix. |
| Run locally | A library: nothing to run. The docs: `make docs-serve`. |
| Stop the local run | Ctrl+C in the terminal of `make docs-serve`. |

## Conventions

- Default branch: `master`. The pre-commit hook `no-commit-to-branch` refuses commits to it.
- Issue tracker: GitHub Issues of this repository; refer to an issue as `#123`.
- Branch names: `<type>/<short-description>`, such as `feat/my-feature` (CONTRIBUTING.md).
- Commit messages: Conventional Commits, enforced by the `conventional-pre-commit` hook (`uv run pre-commit install --hook-type commit-msg`). Pull requests are squash-merged, and release-please reads the squash title, so a pull request's title is a Conventional Commit too.
- Language of pull request titles and descriptions: English.
- Where specs and design notes go: in the pull request description; the repository has no place for them.

## Boundaries

- `CHANGELOG.md` is generated by release-please: never edit it by hand, and never add an `## [Unreleased]` section.
- The version lives in `deadline_budget/__version__.py`, on the line marked `# x-release-please-version`, and in `.release-please-manifest.json`; release-please bumps both. Never change them by hand.
- `docs/agents.md` is part of the public API: it changes in the same pull request as the API (CONTRIBUTING.md, "The agents page").
- Files from the engineering-assets hub (`AGENTS.md` explains how it works) include the copy-page files (`docs/assets/javascripts/copy-page.js`, `docs/assets/stylesheets/copy-page.css`, `overrides/main.html`, `scripts/emit_markdown.py`), `.github/workflows/docs.yml`, `.github/workflows/release-please.yml`, `.github/dependabot.yml`, `.editorconfig` and `CODE_OF_CONDUCT.md`. Change them in the hub; a change here makes the file this repository's own.
- Never publish to PyPI or create a release by hand: release-please creates the release, and `publish.yml` publishes it.

## Notes

- Releases: release-please opens its pull request with the workflow's own token, so CI does not start on it. Close and reopen the release pull request to run CI, then merge it; `publish.yml` publishes to PyPI when the Release Please run completes.
- Tests: every test carries the marker `unit` or `integration` (`--strict-markers`). `tests/integration/` has no tests yet; `make test-integration` would need Docker.
- Code style (CONTRIBUTING.md): type hints on every function, tests included; Google-style docstrings on the public API only; lines up to 120 characters; double quotes; comments only for a non-obvious why.
